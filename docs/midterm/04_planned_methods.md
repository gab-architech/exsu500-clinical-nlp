# IV. Planned Methods

**Models.** We compare five models in three families, all trained on the same split.
(1) *Baselines:* a majority-class reference line, which exposes imbalance artefacts, and a keyword-rule model whose two keywords per class are selected by mutual information on the training set only and which predicts by keyword vote.
(2) *Linear models:* TF-IDF features with class-weighted logistic regression and with a linear SVM. Simple models matched transformers on full clinical documents [8], and logistic regression was as good as complex models once leakage was removed [15].
(3) *Transformer:* Bio_ClinicalBERT [7], fine-tuned with a classification head. The 512-token limit matters here: measured with its own tokenizer, the median note is 652 tokens and 62.5% exceed 512, so the primary setting is head+tail truncation (first and last 256 tokens), which keeps the opening and the impression and retains 59.7% of the dataset's tokens [9]. The robustness check is fixed before any results: on the validation split only, we report macro-F1 separately for notes at or under 512 tokens and for notes over 512 tokens, regardless of the gap. We pre-register that, if the over-512 group's macro-F1 is more than 3 points (0.03) lower than the shorter group's, evaluation is repeated with chunking and late fusion, at most 3 chunks of 512 tokens each (covering about 94% of notes), where the same model scores each chunk and the chunk scores are averaged into one prediction; training is unchanged. This is a fixed decision rule, not a significance test, because per-class subgroup sizes on the validation set are too small for a reliable test. Clinical-Longformer (4,096 tokens, about 8x the compute) is not run and is listed as future work. We prefer supervised fine-tuning to LLM prompting because it is reproducible and fits the compute budget [10].

**Leakage experiment.** Each model is also run on a masked variant of the text with the label strings removed (8.7% of notes contain their own label); the score gap measures how much performance depends on this residual leakage.

**Evaluation.** Macro-F1 is the primary metric because it weights the 11 classes equally despite the 7.2x imbalance. We also report per-class precision, recall and F1, and one-vs-rest AUROC and AUPRC. Uncertainty follows the "Standard" scope: several random seeds for ClinicalBERT and 95% bootstrap confidence intervals on macro-F1, since small test sets can make differences between methods meaningless [16]. We will produce a confusion matrix with error analysis and a reliability (calibration) curve. Hyperparameters are tuned on the validation set only, and the test set is read once, in the final notebook. Test macro-F1 is reported with and without the 9 test notes that have a near-duplicate in another pile. For context we report the best leakage-free macro-F1 on MTSamples, 0.279 [5], while noting that it covers 40 raw labels and is not directly comparable to our 11 classes.

**Compute.** All models run on the Google Colab free tier (one T4 GPU). The baselines and the two linear models train in under a minute each on CPU. A ClinicalBERT run is 3 epochs over the 1,560 training notes at 512 tokens: seconds to about a minute per epoch, and 20 to 30 minutes per **full run** once tokenization, validation evaluation and checkpoint saving are included. The leakage experiment repeats each run on the label-masked text, so three seeds mean six ClinicalBERT runs, **about 2.5 to 3 hours of GPU time in total**; the chunking check adds evaluation-time inference only. This fits inside one free Colab session. The figures are estimates from the step count and will be replaced by measured times after the first Colab run.
